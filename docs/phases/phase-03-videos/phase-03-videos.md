# Phase 03 — Upload e Processamento de Vídeos

## Objective

Deliver complete video management and asynchronous processing capabilities for StreamTube: high-capacity video upload support (up to 10GB using S3 presigned direct-to-storage URLs), background processing queue using BullMQ + Redis, dedicated video processing worker container running FFmpeg (for metadata extraction and thumbnail generation), unique video URLs (12-char native `node:crypto` slugs), HTTP 206 Byte-Range streaming, direct video download, and explicit video status state management.

---

### SI-03.4 — Video Upload Request & Completion API

**Description:** Implement endpoints for initiating a video upload (`POST /videos/upload-url`) and signaling upload completion (`POST /videos/:id/complete-upload`).

**Technical actions:**
- Create DTOs: `CreateVideoUploadDto` (`title`, `original_filename`, `mime_type`, `size_bytes`), `VideoResponseDto`.
- Create `src/videos/videos.controller.ts` protected by `JwtAuthGuard`.
- Endpoint `POST /videos/upload-url`:
  - Validates user channel existence.
  - Generates 12-char native crypto `slug`.
  - Creates video record with status `DRAFT`.
  - Returns presigned PUT upload URL and `videoId`.
- Endpoint `POST /videos/:id/complete-upload`:
  - Validates ownership (must belong to authenticated user's channel).
  - Updates video status to `PROCESSING`.
  - Dispatches job to `video-processing` queue.

**Tests:**

**Acceptance criteria:**

### SI-03.6 — Video Worker & FFmpeg Metadata/Thumbnail Processor

**Description:** Build the video processing consumer (`VideoProcessor`) in the worker process to download video, execute FFmpeg/ffprobe, extract metadata/thumbnail, upload thumbnail to MinIO, and mark video `READY` (or `FAILED` on error).

**Technical actions:**
- Create `src/worker/video-processor.ts` extending `WorkerHost` (`@Processor('video-processing')`).
- Download video stream/file from MinIO S3 bucket to temp directory.
- Execute `ffprobe` to extract duration, width, height.
- Execute `ffmpeg` to capture 1280x720 thumbnail screenshot at 1.0s.
- Upload thumbnail JPEG to MinIO `streamtube-thumbnails` bucket.
- Update PostgreSQL record: status `READY`, `duration_seconds`, `width`, `height`, `thumbnail_key`.
- On error: update status to `FAILED` and record error message in `processing_error`.
- Cleanup temporary files.

**Tests:**

**Dependencies:** SI-03.2, SI-03.5

**Acceptance criteria:**
- Valid video file is processed, thumbnail is generated in MinIO, and status transitions to `READY`.

### SI-03.7 — Video Streaming & Direct Download API

**Description:** Implement public endpoints for video streaming (`GET /videos/:slug/stream`) supporting HTTP 206 Partial Content byte ranges, and direct download (`GET /videos/:slug/download`).

**Technical actions:**
- Endpoint `GET /videos/:slug/stream`:
  - Accepts optional `Range` header (e.g. `bytes=0-1048576`).
  - Verifies video status is `READY` (returns `404 Not Found` if not ready or not found).
  - Streams byte range directly from MinIO using `StorageService.getObjectStream()`.
  - Sets HTTP headers `Content-Range`, `Accept-Ranges: bytes`, `Content-Length`, `Content-Type: video/mp4`, status `206 Partial Content` (or `200 OK` if no range).
- Endpoint `GET /videos/:slug/download`:
  - Returns presigned GET URL with `Content-Disposition: attachment; filename="..."` or streams file with download headers.

**Tests:**

| File | Layer | Verifies |
| :--- | :--- | :--- |
| `src/videos/streaming.controller.spec.ts` | Unit | Range header parsing and response header formatting |
| `src/videos/videos-streaming.e2e-spec.ts` | E2E | Public streaming with HTTP 206 range requests and file download redirect |

**Dependencies:** SI-03.2, SI-03.3

**Acceptance criteria:**
- Anonymous users can stream READY videos without authentication.
- Requesting `bytes=0-1023` returns status `206` with `1024` bytes.
- Requesting a video in `DRAFT` or `PROCESSING` status returns `404 Not Found`.

### API Contracts

| Method | Endpoint | Auth Required | Request Payload | Success Response | Error Response |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `POST` | `/videos/upload-url` | ✅ Bearer JWT | `{ title, description?, original_filename, mime_type, size_bytes }` | `201 Created` `{ video_id, slug, upload_url, status }` | `401 Unauthorized`<br>`403 Forbidden` (No channel) |
| `POST` | `/videos/:id/complete-upload` | ✅ Bearer JWT | None | `200 OK` `Video` object with `status: PROCESSING` | `401 Unauthorized`<br>`403 Forbidden`<br>`404 Not Found` |

| `GET` | `/videos/:slug/download` | ❌ Public | None | `302 Found` (Redirect to Presigned S3 GET URL) | `404 Not Found` |

### Data Model (`Video` Entity Schema)

```sql
CREATE TYPE video_status AS ENUM ('DRAFT', 'PROCESSING', 'READY', 'FAILED');

CREATE TABLE videos (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title VARCHAR(255) NOT NULL,
  description TEXT,
  slug VARCHAR(12) NOT NULL UNIQUE,
  status video_status NOT NULL DEFAULT 'DRAFT',
  original_filename VARCHAR(255) NOT NULL,
  file_key VARCHAR(500) NOT NULL,
  thumbnail_key VARCHAR(500),
  mime_type VARCHAR(100) NOT NULL,
  size_bytes BIGINT NOT NULL,
  duration_seconds FLOAT,
  width INT,
  height INT,
  processing_error TEXT,
  channel_id UUID NOT NULL REFERENCES channels(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_videos_slug ON videos(slug);
CREATE INDEX idx_videos_channel_id ON videos(channel_id);
CREATE INDEX idx_videos_status ON videos(status);
```
